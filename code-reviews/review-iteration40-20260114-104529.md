B2: RFC-0003 PUSE header examples conflict with the RFC’s own wire-format definition (magic/version and Message ID version)
- File(s): spec/06-rfcs/RFC-0003-messaging.md
- Issue: In §11.1 “PUSE Envelope Wire Format” the text says:
  - `magic (5 bytes): "PUSE\x01" (0x5055534501)` (implies magic includes version)
  - `message_id (16 bytes): UUIDv7 bytes`
  
  But earlier in RFC-0003 §3.2 the normative wire format is:
  - Magic is **4 bytes** `"PUSE"` and **Version is a separate 1 byte field**.
  - Message ID is explicitly **UUID v4**.
  
  This is a cross-section contradiction inside the authoritative RFC and can lead to incompatible implementations (header parsing and message ID generation/validation).
- Fix: Make RFC-0003 consistent by choosing one encoding and applying it everywhere:
  - Correct §11.1 to: `magic (4 bytes) = "PUSE"`, `version (1 byte) = 0x01`.
  - Choose a single UUID version for `message_id` (v4 or v7) and update **all** references across RFC-0003 and the non-RFC specs (`spec/03-messaging-sync/interfaces.md` currently states “UUID v4”, and `spec/03-messaging-sync/secure-envelope.md` says “UUID” without committing). If v7 is intended, update §3.2 + interfaces accordingly; if v4 is intended, update §11.1 to v4.
