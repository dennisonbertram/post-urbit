B2: PUSE size constraints internally inconsistent (can imply impossible combinations)
- File(s):
  - `spec/06-rfcs/RFC-0003-messaging.md`
  - `spec/03-messaging-sync/secure-envelope.md`
- Issue:
  - `RFC-0003` §3.2 states:
    - Max envelope size = 1,048,576 bytes
    - Max header extension = 1024 bytes
    - Max ciphertext = 1,048,352 bytes
    These cannot simultaneously hold, because `64 (fixed header) + 1024 (ext) + 12 + 4 + 1,048,352 + 64 (sig) = 1,049,520` > 1,048,576.
  - Both `RFC-0003` and `secure-envelope.md` also label the “minimum header extension” as “Ephemeral/Initial” while using `21` bytes in the size math; but the Initial extension is specified as **33** bytes. (21 bytes corresponds to the Group extension.)
- Fix:
  - Make size limits mutually consistent and unambiguous:
    - Define `MAX_ENVELOPE_SIZE = 1_048_576` as the primary limit.
    - Define `MAX_HEADER_EXTENSION_LEN = 1024` (if desired).
    - Define `MAX_CIPHERTEXT_LEN` **as a function of `ext_len`**:
      - `max_ct_len = MAX_ENVELOPE_SIZE - (64 + ext_len + 12 + 4 + 64)`
      - and require `ext_len <= MAX_HEADER_EXTENSION_LEN`.
    - Update the “minimum size” note to either:
      - (a) state the true global minimum uses the **Group** extension (21), or
      - (b) state per-extension minimums (Initial=33, Ratchet=41, Group=21) and avoid calling 21 “ephemeral/initial”.
