B1: PUSE minimum-size constraint is internally inconsistent and cross-document contradictory - In `spec/06-rfcs/RFC-0003-messaging.md` §3.2, the stated “Minimum envelope size: 177 bytes (21-byte Group extension, 16-byte min ciphertext)” is mathematically wrong (and also contradicts its own “16-byte min ciphertext” statement, plus `spec/03-messaging-sync/secure-envelope.md` which correctly computes 181 bytes). With ChaCha20-Poly1305, ciphertext includes a 16-byte tag even for empty plaintext, so the minimum envelope size must be `64 + ext_len + 12 + 4 + 16 + 64 = 160 + ext_len`; for group ext_len=21, min=181 bytes. - Fix: Update RFC-0003 §3.2 to state **minimum envelope size = 181 bytes** (for ext_len=21) and ideally include the general formula `min = 160 + ext_len` with explicit minima: group=181, initial=193, ratchet=201 (assuming empty plaintext allowed).
