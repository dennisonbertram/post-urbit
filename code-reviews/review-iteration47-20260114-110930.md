B1: `spec/03-messaging-sync/sync-protocol.md` — **CBOR schema contradicts signature/encoding rules for `origin` and `Timestamp.origin`**
- **Problem:** The “CBOR Schemas for Sync Messages” section defines:
  - `SyncOperation.origin: bstr` (20 bytes raw IID) **but**
  - `Timestamp.origin: tstr` (origin IID as Base32 string)
- Later, the **Normative Encoding** section says:
  - `origin` is **20 raw bytes**
  - `timestamp_bytes` uses `SHA256(origin_iid_base32)[0:8]` (hashing the Base32 string), which conflicts with the CBOR schema and with the “origin is raw bytes” rule.
- **Exact fix (choose one consistent representation; recommended = raw bytes everywhere on wire):**
  1) In **CBOR Schemas for Sync Messages**, change `Timestamp.origin` to raw bytes:
     - Replace:
       - `origin: tstr            // origin IID as Base32 string`
     - With:
       - `origin: bstr            // 20 bytes (raw IID)`
  2) In **Timestamp Encoding**, change the hash input to match raw bytes:
     - Replace:
       - `SHA256(origin_iid_base32)[0:8]`
     - With:
       - `SHA256(origin_raw_iid)[0:8]` (where `origin_raw_iid` is the 20-byte IID used in CBOR)
  3) Ensure the `SyncOperation.origin` field and `Timestamp.origin` refer to the same IID bytes (remove any implication they differ).

B2: `spec/02-identity-trust/revocation.md` — **Sequence regression check uses lexicographic string comparison (mathematical error)**
- **Problem:** In `verifyKeyRevocation(...)`, this line is incorrect for decimal strings:
  - `if (replacement_document.sequence <= oldDoc.sequence) { ... }`
  This compares strings lexicographically (e.g., `"10" <= "2"` evaluates true), violating the uint64 monotonicity rule.
- **Exact fix:**
  - Replace:
    ```typescript
    if (replacement_document.sequence <= oldDoc.sequence) {
      return { valid: false, error: 'SEQUENCE_REGRESSION' };
    }
    ```
  - With:
    ```typescript
    if (BigInt(replacement_document.sequence) <= BigInt(oldDoc.sequence)) {
      return { valid: false, error: 'SEQUENCE_REGRESSION' };
    }
    ```
