B1: `spec/02-identity-trust/identity-document-schema.md` — **Contradiction on recovery_proof.status semantics vs. recovery-mechanisms.md (status is informational only).**  
- **Problem:** In **“Signature Verification → For Updated Identity (sequence > 0) → Recovery authorization”**, the spec says:  
  > “If `recovery_proof.status == "pending"`, treat document as provisional until cooldown expires”  
  This makes `status` normative, contradicting `spec/02-identity-trust/recovery-mechanisms.md` (**Normative**) which states verifiers MUST compute pending/active from timestamps and MUST NOT rely on `status`.
- **Exact fix (edit the recovery authorization bullet):** Replace the `status` check with a time check and explicitly declare `status` informational. For example:
  - Replace:
    - “If `recovery_proof.status == "pending"`, treat document as provisional until cooldown expires”
  - With:
    - “Compute recovery finality from timestamps: if `now < recovery_proof.cooldown_expires_at`, treat the document as provisional (pending cooldown); if `now >= recovery_proof.cooldown_expires_at`, treat it as active. The `recovery_proof.status` field is informational only and MUST NOT be used for verification decisions.”
