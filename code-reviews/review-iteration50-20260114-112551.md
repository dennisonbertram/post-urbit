B1: `spec/06-rfcs/RFC-0001-identity-document.md` §12.6 “DHT Verification Rules” is weaker than the normative cross-layer requirements in `spec/00-shared/layer-integration.md` (“DHT Record Format” + “Update Authorization”), creating inconsistent DHT acceptance rules across documents.  
**Problem:** RFC-0001 §12.6 only requires verifying `signatures.current` for identity docs, but `layer-integration.md` additionally requires:
- checking `iid == derive_iid(Base64Decode(keys.signing.genesis))`
- enforcing monotonic `sequence` for updates
- enforcing key continuity via `signatures.previous` when `keys.signing.current` changes, or validating `recovery_proof`

**Exact fix:** Replace RFC-0001 §12.6 with the same normative steps as `spec/00-shared/layer-integration.md` under:
- “Verification (New Records)” (steps 1–4)
- “Update Authorization (Existing Records)” (steps 1–5, including the key-change authorization substeps)

This makes DHT node behavior consistent across the RFC and the shared normative layer.

B2: `spec/06-rfcs/RFC-0001-identity-document.md` §13 “Device Documents” defines fields (`signature_by_identity` for device docs, `signature` for device index) but does not normatively define **signature construction inputs / domain separation**, while `spec/00-shared/layer-integration.md` defines canonical signature schemes and domain separators for both. This is an RFC↔normative-layer mismatch (RFC leaves a protocol-critical detail undefined).  
**Exact fix:** In RFC-0001, add subsections under §13:

1) **Device Document Signature Scheme (v1)** (copy from `spec/00-shared/layer-integration.md` “Device Document Signature Scheme”):
- `signature_input = "post-urbit:device-doc:v1:" || JCS(device_doc_without_signature)`
- `signature_by_identity = Ed25519_Sign(identity_signing_key, signature_input)`
- define `device_doc_without_signature` as the JSON with `signature_by_identity` removed

2) **Device Index Signature Scheme (v1)** (copy from `spec/00-shared/layer-integration.md` “Device Index Signature Scheme”):
- `signature_input = "post-urbit:device-index:v1:" || JCS(device_index_without_signature)`
- `signature = Ed25519_Sign(identity_signing_key, signature_input)`
- define `device_index_without_signature` as the JSON with `signature` removed

Also explicitly reference the domain separator registry values already used elsewhere (same byte strings), so the RFC is self-contained and consistent with the shared normative spec.
