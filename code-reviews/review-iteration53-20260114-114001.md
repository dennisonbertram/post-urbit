B1: **Device Document `endpoints` examples violate the normative Endpoint schema (`priority` is REQUIRED)**
- **Files:**
  - `spec/02-identity-trust/identity-document-schema.md`
  - `spec/06-rfcs/RFC-0001-identity-document.md`
- **Problem:** The canonical Endpoint schema (in both files) states `priority` is REQUIRED (0–255), but the **Device Document** examples omit `priority` inside `endpoints`. This is a cross-document schema contradiction and breaks canonical signing/validation rules for device docs.
- **Exact fixes:**
  1) In `spec/02-identity-trust/identity-document-schema.md`, in the **Device Document** example under “Device Document” (`"endpoints": [...]`), change:
     ```json
     "endpoints": [
       { "type": "direct", "host": "192.0.2.1", "port": 4433, "transport": "quic" }
     ],
     ```
     to:
     ```json
     "endpoints": [
       { "type": "direct", "host": "192.0.2.1", "port": 4433, "transport": "quic", "priority": 0 }
     ],
     ```
     (any valid 0–255 value is fine; `0` matches “highest priority” convention.)

  2) In `spec/06-rfcs/RFC-0001-identity-document.md`, in §13.2 **Device Document** example (`"endpoints": [...]`), change:
     ```json
     "endpoints": [
       { "type": "direct", "host": "192.0.2.1", "port": 4433, "transport": "quic" }
     ],
     ```
     to:
     ```json
     "endpoints": [
       { "type": "direct", "host": "192.0.2.1", "port": 4433, "transport": "quic", "priority": 0 }
     ],
     ```
